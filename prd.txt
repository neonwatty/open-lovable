IMPLEMENTATION PLAN: CONVERTING OPEN LOVABLE TO CLAUDE CODE-ONLY

=============================================================================
CURRENT ARCHITECTURE ANALYSIS
=============================================================================

Current Dependencies:
1. E2B Sandboxes - Remote code execution environment ($)
2. Firecrawl API - Web scraping service ($)  
3. AI Provider APIs - OpenAI/Anthropic/Groq for code generation ($)

Current Flow:
User → Next.js App → E2B Sandbox → AI Provider → Generated Code → Sandbox Preview

=============================================================================
PROPOSED CLAUDE CODE-ONLY ARCHITECTURE
=============================================================================

New Flow:
User → Next.js App → Local Development → Claude Code → Generated Code → Local Preview

Key Transformations:
1. E2B Sandboxes → Local sandbox/ directory with Vite
2. Firecrawl API → Built-in web scraping (fetch/puppeteer)
3. AI Provider APIs → Direct Claude Code integration

=============================================================================
DETAILED IMPLEMENTATION PLAN
=============================================================================

PHASE 1: CREATE LOCAL SANDBOX INFRASTRUCTURE
---------------------------------------------

1. Replace E2B Sandbox Creation (/app/api/create-ai-sandbox/route.ts)
   - Remove E2B SDK dependency
   - Create local sandbox/ directory structure
   - Use Node.js child_process to run npm/Vite commands
   - Set up local React + Vite + Tailwind project
   - Return localhost:5173 as preview URL

2. Update File Operations (/app/api/apply-ai-code-stream/route.ts)
   - Replace Python-based sandbox.runCode() with Node.js fs operations
   - Write files directly to sandbox/ directory
   - Use fs.writeFile, fs.mkdir for file management
   - Implement file watching for hot reload

3. Modify Sandbox Management APIs
   - /api/kill-sandbox → Kill local Vite process
   - /api/restart-vite → Restart local Vite server
   - /api/sandbox-status → Check local process status
   - /api/run-command → Execute commands locally via child_process

PHASE 2: REPLACE EXTERNAL SERVICES
-----------------------------------

4. Replace Firecrawl (/app/api/scrape-url-enhanced/route.ts)
   Option A: Simple fetch-based scraping
   - Use built-in fetch() for basic HTML retrieval
   - Parse HTML with cheerio or similar
   - Extract text content and metadata
   
   Option B: Puppeteer for complex sites
   - Add puppeteer as dependency
   - Handle JavaScript-rendered content
   - Screenshot capability for visual reference

5. Create Claude Code Bridge (/app/api/generate-ai-code-stream/route.ts)
   - Remove all AI SDK imports (@ai-sdk/groq, @ai-sdk/anthropic, @ai-sdk/openai)
   - Create new interface that formats prompts for Claude Code
   - Implement markdown-based code generation format
   - Parse Claude Code responses for file content
   - Stream responses back to frontend

PHASE 3: SIMPLIFY CONFIGURATION
--------------------------------

6. Update Environment Variables
   Remove from .env.local:
   - E2B_API_KEY
   - FIRECRAWL_API_KEY
   - ANTHROPIC_API_KEY
   - OPENAI_API_KEY
   - GROQ_API_KEY
   
   Add (optional):
   - LOCAL_SANDBOX_PATH=./sandbox
   - VITE_PORT=5173

7. Update Dependencies (package.json)
   Remove:
   - @e2b/code-interpreter
   - e2b
   - @ai-sdk/anthropic
   - @ai-sdk/groq
   - @ai-sdk/openai
   - ai (Vercel AI SDK)
   
   Add:
   - cheerio (for HTML parsing)
   - puppeteer (optional, for advanced scraping)

PHASE 4: UI ADJUSTMENTS
-----------------------

8. Update Frontend (app/page.tsx)
   - Remove AI model selector or hardcode to "Claude Code"
   - Update sandbox preview iframe to point to http://localhost:5173
   - Adjust error handling for local environment issues
   - Add indicators for local server status

9. Update Configuration (config/app.config.ts)
   - Remove AI model configurations
   - Update sandbox timeout settings for local processes
   - Adjust file paths for local filesystem

BENEFITS
=============================================================================

1. Cost Savings
   - No E2B sandbox fees
   - No Firecrawl API costs
   - No AI provider API costs

2. Performance
   - Faster local file operations
   - No network latency to remote sandboxes
   - Instant hot reload with local Vite

3. Privacy & Security
   - All code stays local
   - No data sent to third parties
   - Full control over execution environment

4. Developer Experience
   - Easier debugging (local access)
   - Standard local development workflow
   - No API key management

=============================================================================
POTENTIAL CHALLENGES & SOLUTIONS
=============================================================================

1. Security Concerns
   Challenge: Running untrusted code locally
   Solution: 
   - Run in restricted user context
   - Use Docker container for isolation (optional)
   - Implement file system restrictions

2. Port Conflicts
   Challenge: Port 5173 might be in use
   Solution:
   - Check port availability before starting
   - Allow configurable port via environment variable
   - Auto-detect next available port

3. Cross-Platform Compatibility
   Challenge: Commands differ between Windows/Mac/Linux
   Solution:
   - Use cross-platform Node.js APIs
   - Detect platform and adjust commands
   - Use npm scripts for platform abstraction

4. Claude Code Integration
   Challenge: No direct API for Claude Code
   Solution:
   - User manually copies prompts to Claude Code
   - OR: Create a bridge using clipboard or file watching
   - OR: Use browser automation to interact with Claude Code
